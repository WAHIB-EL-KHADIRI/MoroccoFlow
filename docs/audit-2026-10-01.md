## Architecture as built

| Layer         | What exists                                                                                                                  |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Frontend      | Vanilla JS web components + Vite 8, IndexedDB store, mutation outbox, Service Worker/PWA, Chart.js                           |
| Modes         | `demo` (IndexedDB + `src/data/demo.js`, no server) and `company` (API, chosen when `VITE_API_BASE_URL` is set)               |
| Backend       | Fastify 5 modular monolith: `auth`, `resources` (generic CRUD), `team`, `insights`, `files`                                  |
| Database      | PostgreSQL, raw SQL through `pg` (no ORM), one migration `001_initial.sql`                                                   |
| Tenancy       | `tenant_id` on every table, `FORCE ROW LEVEL SECURITY`, `app.tenant_id` set per transaction under a `NOINHERIT` runtime role |
| Auth          | HS512 JWT access tokens, rotating refresh tokens, Argon2id, lockout, TOTP MFA (secret encrypted at rest)                     |
| AuthZ         | Static role → permission table (`lib/rbac.js`), enforced in `preHandler` on every route                                      |
| Audit         | `audit_logs` insert-only for the runtime role (UPDATE/DELETE/TRUNCATE revoked)                                               |
| Reliability   | Optimistic locking (`version`), `Idempotency-Key` table, soft delete                                                         |
| Storage       | S3-compatible, uploads quarantined until a scanner reports `clean`                                                           |
| Jobs / events | **None.** No queue, no scheduler, no domain events                                                                           |
| Tests         | 26 frontend + 33 backend passing (+3 skipped without Postgres), 10 Playwright e2e                                            |

## Domain as built

```
tenants ─┬─ users ── refresh_tokens, user_invitations
         ├─ clients ─┬─ deals            (stage: contact→qualified→proposal→won/lost)
         │           ├─ projects ── tasks
         │           ├─ quotes ─── invoices.quote_id
         │           └─ invoices
         ├─ line_items (quote XOR invoice)  — no API, no UI
         ├─ expenses ── files
         ├─ notifications, audit_logs, idempotency_keys
```

- **Lead** is not an entity: a lead is a `client` with `status = 'prospect'` plus `deals`.
- **Payment** is not an entity: it is the single column `invoices.paid_cents`.
- **No link** quote → project, deal → quote, or project → payment. The core flow
  Lead → Quote → Project → Payment does not exist as data; it is five separate CRUD lists.

## Security audit

| #   | Severity        | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S1  | **MEDIUM**      | **Foreign keys are not tenant-scoped.** `projects.client_id`, `tasks.project_id`, `deals.client_id`, `quotes/invoices.client_id`, `invoices.quote_id`, `expenses.receipt_file_id`, `*_user_id` reference `id` only. PostgreSQL referential-integrity checks bypass RLS, so tenant A can store a reference to tenant B's row id. RLS still hides B's row on read, so this is an integrity break and a (weak, UUID-guarded) existence oracle, not a read leak. Any future join that runs outside RLS (reports, AI context, workers) would turn it into one. **Fix:** `UNIQUE (tenant_id, id)` + composite FKs, added `NOT VALID` then `VALIDATE` in migration 002. **Untested here** (needs Postgres). |
| S2  | LOW → **fixed** | `sales` was granted `finance:quotes`, which no route checks: sales could not create a quote. See "Changes" below.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| S3  | LOW             | `invoices.status` and `paid_cents` are freely writable by `finance:write`. No server-side state machine (e.g. `paid` with `paid_cents = 0` is accepted).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| S4  | INFO            | Every list/insight query relies on RLS for scoping with no explicit `tenant_id` predicate. Correct today; it means RLS is the only line of defence, so it must stay `FORCE`d and covered by the integration tests on CI.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| S5  | INFO            | `POST /notifications` lets `team:write` users target any `userId` in the tenant. Scoped by RLS; acceptable.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

Checked and found sound: parameterised SQL with an identifier allow-list (`crud.js`),
CSV formula-injection escaping, HTML escaping and URL-protocol blocking in the UI,
JWT algorithm/issuer/audience pinning (and tests for `alg: none` and forged tokens),
hashed refresh tokens, IP hashing in audit, upload quarantine, secrets only via env.

## Changes in this phase

- New `quotes` permission namespace; `/quotes` routes now check `quotes:read|write`.
- `sales`, `finance`, `admin`: `quotes:*`. `project_manager`, `viewer`: `quotes:read` (unchanged read access).
- `sales` still cannot read invoices or expenses.
- Tests: route sweep now covers POST/PATCH/DELETE `/quotes`; unit test pins the new grants.
  Both fail against the previous code and pass with the fix.
